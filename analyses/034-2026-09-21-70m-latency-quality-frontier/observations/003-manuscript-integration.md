# Combined scale comparison in the manuscript

The user requested replacing `fig:70m-quality-latency` with the combined
14M/70M loss-latency figure and revising the 70M argument around quality,
threshold strength, transfer overhead, and intervention/kernel co-design.
The analysis PDF is retained as the reproducible source; its byte-identical
copy is `manuscript/draft/figures/02-14m-70m-latency-quality.pdf`.
The figure's methods, coverage and legend remain those in observation 002.

Evidence: `data/combined-figure.json`, generated by `02_combined.py`, and
`data/figure-data.json`, generated by `01_plot.py`. Matched implementation
timings come from Run045 through Analysis028/030. Later T2/Ph kappa=0.5 is
Run047; no sessions are pooled or rescaled. The prose's 0.1-to-0.5 comparison
uses these retained sessions, not a new paired benchmark.

## Checked comparisons

- Native Base: 14M loss 5.208583, latency 0.655442 ms; 70M loss 4.099767,
  latency 1.611048 ms.
- T7/Pall kappa=0.5: loss penalties above Base are 0.620807 (14M) and
  1.116209 (70M). This is an example, not a claim that every recipe's
  degradation grows with size.
- T2/Ph kappa=0 to 0.1: 0.612348 to 0.573427 ms (0.038921 ms reduction)
  at 14M; 2.504098 to 1.955582 ms (0.548516 ms reduction) at 70M.
  These are different trained checkpoints, not matched skipping toggles.
- At 70M, T2/Ph kappa=0.1 to 0.5 changes loss from 4.182317 to 4.838034
  and latency from 1.955582 to 1.214368 ms. Intermediate thresholds are
  explicitly proposed as future work, not assigned interpolated results.
- The same 70M Base checkpoint takes 3.325458 ms in the original port and
  2.732112 ms after optimization, against 1.611048 ms native: excesses
  1.714410 and 1.121064 ms. These are net implementation differences, not
  an isolated measurement of inspection cost.
- Run042 retains 74 candidate directories (opt001--opt074), including
  compilation/numerical failures. Its README documents this additional
  search and selection of opt073 using 16 training inputs. The text calls
  these candidate implementations, not 74 successful optimization steps.
- The fastest 70M candidate is T7/Ph kappa=0.5: 1.088146 ms, 32.4572% below
  native Base, with loss 5.337238 (+1.237471 above Base). The requested
  additional cost is reported in loss units, not milliseconds.
- At T2/Ph kappa=0.1, 1.955582 ms still exceeds same-checkpoint native
  1.662 ms (rounded); see the unchanged appendix implementation table.

The separate controlled 70M result remains in the main text: 1.127766 ms
for the selected path versus 1.365127 ms with native h/z, a 0.237361 ms or
17.4% conditional benefit. Source: Analysis028 `04_controls.py`,
`data/retained-controls.json`, and observation 001. The appendix still
reports the skip-disabled 2.704424 ms control and its inefficient fallback.
The replacement contrast includes fusion/layout differences, while the
headline comparison includes dense optimization and a different checkpoint.

The susceptibility interpretation is scoped to the two measured scales;
the transfer result is scoped to this family and workload. The text motivates
model/size/workload adaptation without claiming that no kernel generalizes.
Only the Results at 70M subsection is replaced. Other author edits remain
unchanged and are excluded from this change's commit.
