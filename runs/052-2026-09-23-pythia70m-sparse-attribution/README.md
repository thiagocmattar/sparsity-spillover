## Question and fixed inputs

Can a kernel exploit the existing T2/Ph h/z zeros at kappa=0.05 and 0.1 to beat
70M native PyTorch Base, while producing a larger positive neighbour latency
drop than the frozen14M kernel? Demonstrate sparse attribution separately from
fusion/dense engineering. Both endpoints must improve; slowing .05 to enlarge
the gap is not progress. Sparse benefit remains distinct from logical opportunity.

Use Run049's verified Run045 c00/c24/c25 step712 checkpoints, unchanged, and
Run041's existing14M c02/c03 endpoints as d05/d10. Model/data seeds1234;
1,493,172,224 training tokens and original AdamW/h-only OL1 histories retained.
No initialization, optimizer step, pruning, threshold change or quantization.
Operational T2=HZ: one-sided h/z gates, equality preserved; h replaces GELU,
z precedes W_o. Preserve biases, BF16 branch rounding and both residual sums.
70M has six D512/FFN2048 layers;14M has six D128/FFN512 layers. Full50304 logits.

The manuscript target is the scaling/latency argument in
`manuscript/draft/05-experimental-study.tex` and execution attribution in
`12-appendix-kernel-validation.tex`. Those replace the historical filenames.
F003 remains valid for Run051: broad h/z exploitation has not been demonstrated.
This run does not pre-approve a manuscript claim or edit TeX.

## Evidence-led starting point

[Prior audit](results/prior-audit.json), generated by `01_audit.py`, reduces only
retained results. Historical positive drops are16.697us at14M and12.774us at70M,
from different sessions. In Run051's instrumented graph traces, global h-index
construction costs18.66/18.55us and gathered multiplication58.11/47.84us across
the five sparse layers. Dense z takes56.34/56.48us across six layers. These are
diagnostic kernel durations, not an additive forecast of full-model speedup.

Run050 already tried packed SIMT, masked split-K, gathered tensor cores and
exact2:4 plus overflow. This run does not rename those as new discoveries. It
first tests eight implementation variants with complete conversion costs:

- E: CTA-local active-feature compaction and BF16 WMMA, token groups4/8/16,
  output tiles64/128, reduction chunks16. It removes global index storage and
  the separate packing launch, but repeats inspection for each output tile,
  retains row padding, and has shared-memory/barrier costs.
- F: direct warp-ballot scans and FP32 FMA with4/8 outputs per lane, four rows
  per block. It is a scheduling variation of prior direct sparse consumers,
  not a new algorithm family. It avoids global packing but may lose weight
  reuse or spend too long on serial nonzeros. It has no row-NNZ truncation.

Frozen Run050 C and three dense implementations remain controls. Every site
and layer enters the screen, with priority on z, then existing h metadata costs,
then h layer0. The C control has no reported spills; larger scalar cutoffs are
not the starting strategy. All new kernels have skip-disabled controls and
write actual counts checked against independent masks. No performance is known
for the new code before the GPU smoke.

## Adaptive schedule and decision points

1. Verify all immutable inputs and run operator checks plus a four-block full
   model smoke before accepting new paths. Keep build/numerical failures.
2. Reproduce14M K050 and70M prior C with native and strong dense controls, full
   numerical validation and three interleaved process rounds on one RTX5090.
3. Screen complete component paths on literal training blocks0:64 and64:128,
   both kappas, five randomized paired passes. These are development and
   confirmation inputs, not an untouched statistical holdout. Validation is
   never used to select a candidate or dispatch.
4. Promote a component only if qualified and at least5% faster than the prior
   complete path at both kappas and in both training splits. Integrate early;
   require full-model improvement over prior C and optimized dense at both
   endpoints before final freeze. A component winner is not a final result.
5. Use measured conversion/consumer costs to choose at most eight follow-up
   variants. Candidate versions are appended and frozen per attempt, never
   overwritten after execution. Producer fusion, occupancy-based scheduling or
   an alternate sparse family are contingent choices, not implemented claims.
   Changing scientific inputs, scope or budget requires a new decision.
6. Freeze the selected policy and rerun the interleaved14M/70M matrix. Retain
   h-only/z-only replacements and same-layout h-off/z-off/both-off controls.
   Stop and report a negative result if no qualified improvement emerges.

`09_execute.py` runs one explicitly selected stage sequentially. It does not
choose research direction or automatically continue into final evaluation.
`05_select.py` uses training measurements only; `07_freeze.py` requires both
full-model training checks and unchanged source before sealing a final policy.
The initial scripts can be reviewed before any billable resource is created.

## Measurement and interpretation

RTX5090, BF16/FP32 accumulation, batch1, sequence2048, uncached full forward,
CUDA graphs. Static weight preparation, compilation/capture and equal input
staging are excluded; every recurring scan, packing step, dispatch, metadata
write, gather, projection and complete logits are included. Disable TF32 and
reduced-precision BF16 reductions. Pinned Run049 environment is reused.

Every final implementation is checked against its checkpoint's native eager
reference on all500 MiniPile validation documents:338 complete blocks,
692224 input tokens,691886 predicted tokens,1444-token tail excluded. Preserve
the existing bounds: per-logit abs(error)<=.25+.02*abs(reference), per-block
relativeL2<=.02 and pooled loss difference<=.001. No post-hoc relaxation.
Report canonical historical FP16 loss separately from BF16 numerical checks.

Each checkpoint/backend has64 common timing inputs x7 paired passes x3 fresh
processes. Interleave conditions/sizes by process round, retain input identity
across all cells, and bootstrap process rounds and input blocks jointly.
Report signed effects and uncertainty; do not average percentages.

- Practical target: both70M sparse endpoints beat the same-session native Base.
- Sparse attribution: both endpoints beat all qualified strong dense controls;
  same-layout skipping switches retain checkpoint/gates/fusion and show a
  benefit. An inefficient skip-disabled path is not the practical denominator.
- Original cross-size target: delta=L(.05)-L(.1), with a positive lower95%
  interval for delta70-delta14 and a positive drop at each size.
- Dense-adjusted secondary contrast: G(k)=D(k)-L(k), A=G(.1)-G(.05), and
  A70-A14. This does not replace the user's original target.
- Broad h/z claims require evidence for z, including its conditional effect
  with h enabled; retain interaction and negative effects. A h-only result is
  labelled h-only even if the overall latency targets pass.

The eight kernels may fail. A larger gap is not itself proof of causal sparse
attribution, and differences between trained kappas do not isolate the training
effect of threshold alone. This is one seed, one GPU SKU and one workload,
not a general scaling law or decode/serving result.
