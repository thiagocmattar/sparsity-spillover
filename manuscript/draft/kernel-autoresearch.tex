\subsection{When model-wide sparsity translates to speedup}
\label{sec:kernel-autoresearch}

We evaluate all 30 Pythia-14M checkpoints with the same specialized K050
implementation on one RTX5090: BF16, batch-size-one, uncached 2,048-token
inference with full-vocabulary logits. Complete-validation numerical
qualification precedes timing on 64 fixed inputs, seven paired passes and
three processes (Appendix~\ref{app:kernel-results}). We use absolute
latency versus validation loss as the deployment comparison, and recommend
the \emph{projection-only} variant for this measured cohort: disabling
attention skipping improves every checkpoint.

\textbf{The sparsest model is not the fastest optimized model}
(Figure~\ref{fig:kernel-autoresearch}a). At $\kappa=0.5$, four-site OL1
takes $0.45175$ ms with loss 6.0380; seven-site OL1 takes $0.46837$ ms with
loss 5.8294. Neither dominates the other on quality and latency. With both
sparse paths enabled, their latencies are $0.45948$ and $0.47337$ ms.
Yet seven-site reports a larger native-relative speedup, $1.783\times$
versus $1.609\times$, because its native reference is slower: $0.84409$
versus $0.73944$ ms. The native implementation executes additional Q/K/V
gates separately, whereas K050 fuses them into existing operations. This
supports an overhead explanation without isolating each operation's cost.

Let $t_N,t_0,t_P,t_K$ be native, optimized all-skips-off, projection-only,
and full K050 latency. The ratio decomposes as
\[
\frac{t_N}{t_K}=\frac{t_N}{t_0}\frac{t_0}{t_P}\frac{t_P}{t_K};
\qquad 1.783\simeq1.360\times1.325\times0.989
\]
for seven-site OL1 at $\kappa=0.5$. The first factor includes dense-kernel
and layout changes as well as fusion. Projection skipping is profitable;
attention skipping is not. A common native A0 reference instead gives
$1.427\times$ and $1.385\times$ for the four-/seven-site full K050 pair;
these cross-model ratios still include implementation changes and quality
differences (Appendix~\ref{app:kernel-diagnostics}).

\textbf{Instruction bypass tracks projection benefit more closely than
scalar zeros alone.} Across the cohort, projection MMA bypass is associated
with projection-skipping gain at $R^2=0.946$, compared with $0.413$ for the
projection scalar zero-product fraction. Entire activation fragments can
permit bypassing matrix multiply--accumulate (MMA) instructions; very sparse rows may instead
use scalar arithmetic. These are kernel-exploitable zero-fragment patterns,
not an imposed structured-sparsity constraint. At $\kappa=0.5$, four-site
OL1 bypasses $82.30\%$ of projection MMAs versus seven-site's $57.68\%$.

Seven-site's additional attention opportunity supplies the boundary case.
The same checkpoint skips $58.00\%$ of eligible QK and $67.21\%$ of PV
instructions, but attention skipping adds $5.00$ microseconds overall.
Detection and control recur after fragment loads, and zero QK scores still
participate in softmax. Counts of skipped instructions therefore need not
translate into net time savings. This is a property of the tested kernel,
shapes and hardware, not evidence that attention sparsity is intrinsically
unprofitable.

The implementation was developed through a human-guided coding-agent loop
configured with GPT-6 Astra~\citep{openaigpt6astra}; search history and
compatibility checks are in Appendix~\ref{app:kernel-results}. The scientific
result is conditional realization: projections expose profitable skipping,
while additional attention sparsity and a larger native-relative ratio do
not identify the lowest-latency representation.
