# Local numerical qualification of the corner consumer

## Question

Was Run063's real-checkpoint numerical failure caused by the new corner-only
consumer, and can that consumer execute the unchanged tile models within the
existing numerical contract?

## Method and coverage

Retain the original failed two-block kappa0 comparisons. Trace the first real
validation block with identical native hidden inputs supplied independently to
each of the six layers. Compare each normalization, input projection, rotary
transform, attention and fused output projection/residual using identical
operands. Profile native SDPA dispatch, then substitute native SDPA only for
the shared frozen attention component in the optimized graphs.

Finally compare native, generic sparse/no-skip and specialized sparse/no-skip
graphs against each checkpoint's own eager reference on the existing local
RTX5070TiLaptop. Both original step712 seed1234 T2/Ph checkpoints at kappa0/.1
are unchanged, as are their corner8x16 gates. Each comparison uses all500
MiniPile validation documents:338 complete2048-token blocks,692224 input
tokens,691886 predictions, and the excluded1444-token tail.

Bounds remain elementwise logit atol.25/rtol.02, relativeL2<=.02 and absolute
pooled loss difference<=.001. No tolerance or data coverage is weakened.

## Result

The original failure affects all four optimized paths. Native graph versus
native eager has zero error. Optimized paths have identical saved summaries:
max logit differences1.375/1.25, relativeL2.003471/.003757, loss difference
-.0018486466. RelativeL2 passes; elementwise and pooled-loss checks fail.

On equal real operands, every traced normalization, QKV/W1 projection, RoPE/V
layout and generic fused h/z projection/residual matches native exactly.
Only the shared K035 attention result differs, with per-layer max error
.0078125–.015625 on this block. Native local dispatch is Flash SDPA. Matching
native SDPA in the shared optimized attention path removes the original
two-block failure for both consumers, with exact logit/loss equality.

Full local qualification then passes every graph at both thresholds with
**zero observed logit error and zero pooled loss difference on every block**.

## Caption and interpretation

No publication figure is needed for this pre-launch qualification record.
The result establishes full local numerical equality of the unchanged corner
consumers under matched native attention. It isolates the previous smoke
failure to the shared attention component used on the laptop. It does not
establish a latency advantage.

## Caveats

K035 freezes a two-split64x256 attention schedule measured for RTX5090. The
CUDA profiler in `prelaunch/attention-backend-002.json` records the laptop's
native nonsplit128x128 Flash kernel on its46-SM GPU. This controlled
substitution identifies the shared component causing the mismatch; it is not
a repair or full qualification of K035 on other GPUs. No exact internal
floating-point cause or gate-decision-flip count is claimed here.

Production RTX5090 retains frozen K050/K035 in both consumer families and all
controls. It must pass fresh component checks, both smokes and complete own-eager
qualification before accepted results. The executable rejects other GPUs and
has no native-attention substitution option. Laptop BF16 losses are not
interchangeable with previous RTX5090 or canonical FP16 quality measurements.
The trained tile models' quality penalty remains. No cloud experiment or new
speedup measurement has been launched, and no manuscript finding is promoted.
